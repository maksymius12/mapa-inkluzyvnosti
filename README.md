## Проблема

У Києві проживає понад 147 тисяч людей з інвалідністю. Заздалегідь майже неможливо дізнатися, чи є в закладі пандус, чи пройде візок у двері, чи немає порога. Людина їде на місце й там розуміє, що зайти не вийде.

Існуючі сервіси закривають проблему лише частково:

| Можливість | Wheelmap | Мапа безбар'єрності | Мапа Інклюзивності |
|---|---|---|---|
| Стандартизована оцінка | Груба, 3 кольори | 55 критеріїв | 7 критеріїв |
| Хто може перевіряти | Будь-хто | Лише фахівець | Будь-хто, до 1 хвилини |
| Маршрут із бар'єрами | немає | немає | є |
| Аналіз фото ШІ | немає | немає | є |
| Запит допомоги | немає | немає | є |

## Як це працює

1. **Вхід** через email, Google або в режимі гостя
2. **Карта** із мітками закладів: колір означає категорію, значок у куті означає доступність
3. **Картка закладу** з повною інформацією про доступність
4. **«Як дійти»**: маршрут із підсвіченими бар'єрами на шляху

### Статуси доступності

| Статус | Значення |
|---|---|
| Зелений | Усі 7 критеріїв виконано |
| Жовтий | Частково доступно |
| Червоний | Відсутній хоча б один критичний критерій |
| Пунктир | Ще не перевірено |

## Швидка перевірка за 7 критеріями

Методика спирається на офіційні вимоги до безбар'єрності. Перевірка займає менше хвилини.

**Критичні** (якщо «ні», статус стає червоним):
1. Пандус
2. Ширина дверей від 0,8 м
3. Поріг до 2 см

**Додаткові:**

4. Ліфт або перший поверх
5. Доступний туалет
6. Тактильні позначки
7. Допомога персоналу

## Ключові можливості

- **Маршрути з бар'єрами.** Застосунок не лише показує точки, а веде шляхом і попереджає про перешкоди.
- **Ранкова перевірка маршрутів.** Щодня о 7:00 збережені маршрути перевіряються заново, а користувач отримує сповіщення, якщо з'явилась нова перешкода.
- **Аналіз фото штучним інтелектом.** Фото входу аналізується моделлю, яка пропонує покращення. ШІ може лише знизити статус закладу, але ніколи не підвищити.
- **Запит допомоги.** Сигнал волонтерам поруч. Це не екстрена служба і не заміна 112.
- **Ролі користувачів.** Мешканець або волонтер, а також різні можливості для учнів і дорослих.
- **Обране, пошук, налаштування теми.**

## Технології

| Шар | Інструменти |
|---|---|
| Мова та інтерфейс | Kotlin, Jetpack Compose (Material 3) |
| Архітектура | ViewModel, StateFlow, Navigation Compose, Koin |
| Карта | osmdroid, OpenStreetMap |
| Маршрути | OSRM |
| База даних і авторизація | Supabase (PostgreSQL, PostGIS, Auth, Storage, Edge Functions) |
| Аналіз фото | Модель ШІ через серверну функцію Supabase |
| Push-сповіщення | Firebase Cloud Messaging (лише для сповіщень) |
| Фонові задачі | WorkManager |

## Безпека

- Секретні ключі зберігаються лише на сервері й не потрапляють у застосунок чи репозиторій.
- Ключ ШІ-моделі використовується тільки в серверній функції.
- Доступ до даних обмежений політиками Row Level Security.
- Завантаження фото доступне лише авторизованим дорослим користувачам.

## Запуск

1. Відкрий проєкт в Android Studio.
2. Створи файл `local.properties` у корені проєкту. Він знаходиться в `.gitignore` і не потрапляє в репозиторій.

```properties
SUPABASE_URL=https://YOUR-PROJECT.supabase.co
SUPABASE_ANON_KEY=YOUR-PUBLISHABLE-KEY
GOOGLE_WEB_CLIENT_ID=YOUR-WEB-CLIENT-ID.apps.googleusercontent.com
```

3. Для push-сповіщень додай свій `google-services.json` у папку `app/`.
4. Запусти застосунок на емуляторі або пристрої.
