# Підтвердження пошти й скидання пароля 6-значним кодом

Застосунок не використовує посилань у листах (раніше вони вели на `localhost` — Site URL проєкту — і не відкривалися на телефоні).
Замість цього користувач вводить 6-значний код із листа на екрані «Введіть код».

| Сценарій | Виклик у застосунку (supabase-kt 3.8) | Шаблон листа в Supabase |
|---|---|---|
| Реєстрація | `signUpWith(Email, redirectUrl = null) { data = … }` → `verifyEmailOtp(OtpType.Email.SIGNUP, email, token)` | **Confirm signup** |
| Повторний код реєстрації | `resendEmail(OtpType.Email.SIGNUP, email)` | **Confirm signup** |
| Скидання пароля | `resetPasswordForEmail(email, redirectUrl = null)` → `verifyEmailOtp(OtpType.Email.RECOVERY, email, token)` → `updateUser { password = … }` | **Reset password** |

Повторний код для скидання пароля — це знову `resetPasswordForEmail` (ендпоінт resend у Supabase не підтримує тип recovery).

## Налаштування в Supabase Dashboard

1. **Authentication → Sign In / Providers → Email**
   - Confirm email: увімкнено.
   - Email OTP Length: **6**.
   - Email OTP Expiration: **3600** секунд (1 година; застосунок так і пише користувачу).
2. **Authentication → Emails → Templates** — у шаблонах **Confirm signup** і **Reset password** має бути `{{ .Token }}`
   і не має бути `{{ .ConfirmationURL }}` (інакше в листі знову з'явиться посилання).
3. **Authentication → Rate Limits** — вбудована поштова служба Supabase має дуже низький ліміт листів на годину;
   для реальних користувачів підключіть власний SMTP (Authentication → Emails → SMTP Settings).

Site URL / Redirect URLs для цих листів більше не потрібні. Вхід через Google працює через ID-токен
(Credential Manager) і від них теж не залежить.

## Приклади шаблонів

**Confirm signup** — тема: `Код підтвердження — Мапа Інклюзивності`

```html
<h2>Підтвердження пошти</h2>
<p>Вітаємо в «Мапі Інклюзивності»!</p>
<p>Ваш код підтвердження:</p>
<p style="font-size:28px;font-weight:bold;letter-spacing:6px">{{ .Token }}</p>
<p>Введіть його в застосунку. Код діє 1 годину.</p>
<p>Якщо ви не реєструвалися, просто проігноруйте цей лист.</p>
```

**Reset password** — тема: `Код для зміни пароля — Мапа Інклюзивності`

```html
<h2>Зміна пароля</h2>
<p>Ваш код для зміни пароля:</p>
<p style="font-size:28px;font-weight:bold;letter-spacing:6px">{{ .Token }}</p>
<p>Введіть його в застосунку. Код діє 1 годину.</p>
<p>Якщо ви не просили змінити пароль, проігноруйте цей лист — пароль лишиться тим самим.</p>
```

## Як поводиться застосунок

- Після реєстрації відкривається «Введіть код» («Ми надіслали 6-значний код на …»). Після правильного коду
  створюється сесія, профіль уже створив серверний тригер `handle_new_user_profile` з метаданих реєстрації, відкривається мапа.
- «Надіслати код ще раз» доступна через 60 секунд після попереднього листа.
- Supabase повертає ту саму помилку `otp_expired` і для невірного, і для простроченого коду; застосунок пише
  «Невірний або прострочений код», а якщо від надсилання минуло понад годину — «Термін дії коду минув. Надішліть новий код».
- Після 5 невдалих спроб кнопка «Підтвердити» блокується на 30 с, далі 60, 120, 240, 300 с (плюс серверні ліміти Supabase).
- Якщо пошта не підтверджена, а користувач намагається увійти, застосунок пропонує надіслати новий код і відкриває той самий екран.
- «Забули пароль?» завжди показує «Якщо акаунт із поштою … існує, ми надіслали код» — наявність акаунта не розкривається.
  Після коду — «Новий пароль» (щонайменше 6 символів, як при реєстрації), потім «Пароль змінено» і мапа.
  Якщо вийти з екрана «Новий пароль» без збереження, тимчасова сесія скидання закривається.
